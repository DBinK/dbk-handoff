# 上下文接手恢复（dbk-pickup）

作为读取 `.agent/handoff/` 交接报告的唯一入口，按渐进式加载原则恢复任务上下文，校验协议版本与工作区 Git 状态，向用户汇报对齐并经确认后再继续推进任务。

## 工作流

### 1. 解析路径并读取交接报告

按“显式指定优先、`latest.md` 兜底”的顺序读取报告：

1. **显式指定**：若用户指令或引导 Prompt 中给出了具体的交接报告路径（如 `<workspace>/.agent/handoff/<YYMMDD>-<HHMM>-<task>.md`），直接读取该指定文件。
2. **缺省兜底**：若用户未附带具体路径（如直接调用 `/dbk-pickup`），默认读取 `<workspace>/.agent/handoff/latest.md`。由于 `latest.md` 与权威快照内容完全一致，**读取后直接使用其正文即可，无需再次读取 `snapshot` 字段指向的同名快照文件**（`snapshot` 字段仅用于标识快照归属与汇报引用）。
3. **缺失处理**：若指定文件或 `.agent/handoff/latest.md` 不存在，列出 `.agent/handoff/` 下已有的快照供用户选择，或告知用户当前工作区尚无交接报告。

### 2. 校验报告元数据（Frontmatter）

读取报告后，先核对开头的 YAML frontmatter：

1. **协议版本校验（`handoff_version`）**：
   - 当前支持的版本为 `1`。
   - 若报告中的 `handoff_version` 高于 `1`，必须先提示用户“当前交接报告版本高于本技能支持版本，将降级按纯文本阅读”，不要强行套用旧版字段假设。
   - 忽略未识别的扩展字段，保持向后兼容。
2. **Git 工作区状态比对（`git`）**：
   - 若报告包含 `git: { branch, head, dirty }` 字段，用只读 Git 命令检查当前工作区的实际分支、HEAD 短哈希与未提交变更状态；比对 `dirty` 时忽略 `.agent/` 路径，交接产物本身不算工作区变更。
   - 若分支切换、HEAD 移动或 `dirty` 状态与报告记录不一致，在向用户汇报时**必须明确指出“交接后工作区已发生变化（说明具体差异）”**，并在动手修改代码前等待用户确认。

### 3. 渐进式加载与防 Token 爆炸约束

1. **聚焦核心工作集**：根据报告中的 `🎯 任务目标`、`📂 核心工作集`、`✅ 已完成事项`、`💡 关键决策与避坑指南` 和 `⏳ 当前停顿点与下一步待办` 建立任务全貌，仅按需读取下一步待办直接涉及的工作集文件，避免全仓盲目搜索。
2. **严守避坑指南**：仔细阅读报告中列出的 `已踩坑/已排除` 方案，不得重复尝试已被前序 Agent 证伪的做法。
3. **禁止盲读原始会话日志（`transcript`）**：
   - **严禁主动一次性通读原 Agent 的完整 Transcript 日志文件**。
   - 只有在交接报告缺失关键细节导致无法推进、报告提供了有效 `transcript` 路径且获得用户授权时，才使用行范围或关键词局部检索所需片段。

### 4. 向用户对齐状态并等待确认

读取与校验完成后，用简短 3~4 句话向用户汇报：

- **快照与状态**：已读取的快照标识（`snapshot`）及 Git 工作区状态是否与交接时一致。
- **目标与现状**：已理解的任务目标、已完成进展与当前停顿点。若交接报告包含需求对照矩阵（`Spec & Baseline`），优先按需求宏观坐标复述（如“对照 PRD 已完成 M/N 项，当前停留在第 X 项……”）。
- **避坑与待办**：已留意的避坑约束，以及接下来准备执行的第一步具体动作与自测方案。

遵循以下行动边界：
- **默认先停下来等待确认**：完成上述汇报后**立即结束本轮回复并等待用户确认**，在此之前只允许执行只读检查，**禁止在同一轮直接修改任何文件或运行待办中的非只读命令**。
- **例外**：仅当用户在粘贴引导 Prompt 之外，额外附加了明确的立即执行指令（如“不用等我确认，直接开始改”）且工作区 Git 状态一致时，才可在汇报后直接执行待办第一步。

## 注意事项

- 未加载本技能指引时，不要跳过元数据校验直接裸读 `.agent/handoff/latest.md` 开工。
- 若报告标记 `git.dirty: true`，接手时先通过 `git status -s` 和 `git diff` 查看工作区现有的未提交改动，分清哪些是前序 Agent 已完成的部分、哪些是停顿点留下的半成品，切勿盲目执行 `git checkout` 或 `git reset` 抹掉前序改动。
